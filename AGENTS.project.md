## What this is

`agent-rules` is the shared AI-agent guidance for our projects: the `rules/*.md`
modules plus a zero-dependency Node CLI (`bin/agent-rules`) that vendors them into
each project's `AGENTS.md`. This repo **dogfoods its own guidance** — the
`AGENTS.md` you are reading was generated by the CLI from this repo's own rules
(`source: "."`). See the README for the full model, the new-project checklist,
and the release flow.

## Layout

- `rules/` — the shared rule modules (`_intro`, `core`, `language`, `commits`,
  `pull-requests`, and per-stack `rust` / `typescript-react` / `godot`).
- `bin/agent-rules` — the sync CLI (Node, zero dependencies).
- `templates/` — starters copied into a project: `.agentrules.json`,
  `AGENTS.project.md`, and the drift-check workflow `agent-rules.yml`.
- `consumers.json` — repos the release fan-out targets. This repo is deliberately
  **not** listed: it is the source, not a downstream consumer.
- `VERSION` — the version the CLI stamps into every generated `AGENTS.md`.
- `.github/workflows/` — `release.yml` (tag → dispatch fan-out) and
  `self-check.yml` (verify this repo's own `AGENTS.md` is in sync).

## Working on the rules

- Edit `rules/*.md`, then re-run `node bin/agent-rules sync` so this repo's own
  `AGENTS.md` stays current (the `self-check` workflow enforces it).
- Rules are **traps to avoid** — keep them non-obvious, specific, and repeatedly
  hit; the meta-rules at the top of any generated `AGENTS.md` apply here too.
- Cut a release by bumping `VERSION` and tagging `vX.Y.Z` (README → *Cutting a
  release*); that fans out a bump PR to every consumer.

## Build & test

No build step — the CLI is plain Node:

```bash
node bin/agent-rules sync            # regenerate this repo's AGENTS.md
node bin/agent-rules sync --check    # verify it is in sync (used by self-check CI)
```
